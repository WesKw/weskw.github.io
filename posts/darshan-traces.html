The ATLAS project at CERN has a smaller internal team called the Software Performance Optimization Team (SPOT) that monitors various performance metrics of ATLAS workflows. They use a web-based performance monitoring dashboard that mainly focused on measuring CPU, memory, and some I/O performance using the performance monitoring tool PrMon. However, data analysis workflows done by ATLAS have slowly been shifting from offline / local workflows to online workflows powered by HPC. So, the new peformance bottleneck has been shifting away from CPUs and moving towards I/O. This project was started as a way to introduce I/O performance monitoring of ATLAS workflows using Darshan I/O.

I was one of the main collaborators for this project, writing the scripts that run ATLAS workflows with Darshan I/O and generated plots for the Dashboard. This project was recently completed, and allows for the monitoring of general I/O metrics and redundant read operations on various ATLAS workflows. A paper has been submitted to the 28th Conference on Computing in High Energy and Nuclear Physics (CHEP) but is not yet published. A complete write-up by my mentors can be found here.

As for my own personal thoughts on this project, I thought this was a really good way to bridge the gap between Computer Scientists and Domain Scientists. I find that sometimes when a computing side to a domain science is introduce, important aspects like performance often get ignored. Compute is often seen as a "means to an end" rather than its own science (which isn't necessarily a bad perspective, mind you). With ATLAS moving analysis to HPCs and compute becoming more expensive than it has ever been, being able to squeeze the maximum performance out of the small amount of compute time available becomes extremely important. In any case, I really enjoyed collaborating with Argonne and CERN scientists on this project.
